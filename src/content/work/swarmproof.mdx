## The problem

An agent that says "fixed" proves nothing. <Src l="14" /> Before you merge an agent's change you need 3 things: proof that it passes your tests, proof that nobody edited the tests to get there, and a record you can check later without calling a model again.

## What I built

The README is in French; this page renders it in English.

- `swarmproof fix` runs Claude and Codex on a throwaway copy; the source repository is never modified. <Src l="47-50" />
- It ignores the engine's own "completed" status and computes success from each agent's result. <Src l="57-58" />
- It restores the test files from the clean copy before judging, so <Mark l="60-61">a fix cannot pass by editing the tests</Mark>.
- Your test command gives the verdict: `PASS`, `FAIL`, or `INCONCLUSIVE` when infrastructure fails. <Src l="62" />
- An Evidence Pack with a SHA-256 manifest that `swarmproof verify` checks offline. <Src l="64-67" />

## How it is verified

- 97 tests in a standard-library suite that runs in about 1.4 s, per README. <Src l="248" />
- GitHub Actions [CI](https://github.com/yannabadie/swarmproof/actions/workflows/ci.yml): the latest run on `main` passed on 5 November 2026.
- Demo pack v2 is a real multi-file run: PASS on 4 tests, a fix applied atomically to 2 files, and `shasum -a 256 -c manifest.sha256` OK on 30 files, per README. <Src l="125-144" />
- An independent red team tested v0.1. 3 critical vulnerabilities were fixed in v0.2, with regression tests in `tests/test_security.py`. <Src l="198-199" />

## What this means for your project

- You can accept an agent's fix on evidence: your tests, restored before judging, decide. That is an **Agent or MCP build**.
- Reviewers get a pack they can verify offline, without model calls and without trusting the agent.
- An **Architecture review** can check whether your tests are strong enough to act as the judge.

## Status & limits

- Alpha, v0.2.1, released 5 November 2026. <Src l="23" />
- The pack proves internal consistency, not origin. It is not signed yet, so it does not prove who produced it. <Src l="17-21" />
- One run on one repository: a feasibility proof, not a statistical study. It does not show that a swarm beats a single agent. <Src l="28-29" /> <Src l="230" />
- It needs executable tests. If your tests are weak, the verdict is weak. <Src l="226" />
