## The problem

France's e-invoicing reform makes structured invoices such as Factur-X mandatory. Per README, every company must be able to receive them from 1 September 2026, and small companies must issue them from 1 September 2027. <Src l="42-44" /> A plain office PDF no longer qualifies. <Src l="228" /> Finance teams need to catch a bad file before a platform rejects it.

## What I built

The README is in French, with an English summary. <Src l="240" />

- A single-file validator, standard library only: no pip install, no C compiler. <Src l="9" /> <Src l="68" />
- Extraction of `factur-x.xml` from hybrid PDF/A-3 invoices, with checks on `/AF` and XMP metadata. <Src l="11" />
- Validation of CII XML against the Factur-X 1.0.07 / EN 16931 profiles, MINIMUM to EXTENDED. <Src l="12" />
- An audit of <Mark l="13">the 4 new mandatory French invoice mentions</Mark>, including the buyer's SIREN checked with Luhn.
- A reusable GitHub Action that annotates failing files in pull requests. <Src l="167" />

- Release v1.0.0, used by the Action as `yannabadie/facturx-france-2027@v1.0.0`. <Src l="4" /> <Src l="181" />

- Sample PDF/A-3 and XML invoices ship in the repository. <Src l="77" />

## What this means for your project

- Compliance as code: a CI gate fails the build before a bad invoice reaches a platform. When an agent prepares invoices, that is part of an **Agent or MCP build**.
- With zero dependencies it runs where installs are locked down, such as a CI runner or an Alpine container. <Src l="68" />
- Exit codes and JSON output plug into an ERP job or a webhook. <Src l="93-97" />
