## The problem

A model checking its own work misses its own mistakes, and an orchestrator can report success on a step that failed. <Src l="19" /> Teams that use several providers also need failover, one place for access control, and a log of every action.

## What I built

The README calls the platform NEXUS. <Src l="1" />

- 7 native SDK drivers (Anthropic, Google, OpenAI, DeepSeek, Kimi, MiniMax, Ollama), each with its own circuit breaker and failover, and no wrapper library. <Src l="17" />
- Cross-model verification: <Mark l="19">the opposite model validates each tool execution</Mark> before the pipeline advances.
- Security layers on by default: InputGuard, OutputGuard, PathGuardian, ShadowRedTeam, RBAC and AuditLogger. <Src l="21" />
- Tool execution in a Docker sandbox by default; running on the host is opt-in. <Src l="286" />
- A research CLI that writes a reproducible evidence pack with a SHA-256 manifest. <Src l="76" />

## How it is verified

- A pytest suite under `tests/`. The README's coverage command fails below 60%. <Src l="329-332" />
- Test counts are published per CI run in an `evidence-ledger` artifact, not hard-coded in the README. <Src l="341" />
- ShadowRedTeam runs automated red-team tests of agent outputs. <Src l="279" />
- The last fully green [CI run](https://github.com/yannabadie/nexus-swarm-os/actions) was on 17 March 2026.

## What this means for your project

- If you use more than one model provider, failover and a second-model check can live in the orchestration layer instead of in each prompt. That is an **Agent or MCP build**.
- RBAC and an audit log come with the first release, not after the first incident.
- An **Architecture review** can decide where a second-model check is worth its cost.
